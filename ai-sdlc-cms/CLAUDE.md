# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

CMS that tracks real projects through the AI-SDLC v5.9 process (14 steps, per-step checklist, 8 gates, output documents, audit log). The UI and content are Vietnamese. Backend: Fastify JSON API with JSON-file storage, no database. Frontend: React 18 + plain Ant Design 5 (Pro Components was removed to cut bundle size) + TanStack Query + React Router (routes lazy-loaded), built with Vite in `web/`. This directory lives inside the static process site repo (`..` = `E:codeai-sdlc`, own `.git` here, nested), which is the source of truth for the process definition.

## Commands

```bash
npm run build       # install + build web/ → web/dist (needed before npm start serves the UI)
npm start           # node server.js, http://localhost:3300 (PORT, HOST, CMS_DATA env)
npm run dev         # dev.js: node --watch server.js (API, PORT default 3300) + Vite HMR on :5173 proxying /api
npm test            # node test.js && node test-telegram.js — API flow via fastify.inject in a temp data dir, plus Telegram against a fake Bot API; no port or network needed
npm run typecheck   # tsc --noEmit for web/
npm run sync        # node sync-process.js [path/to/site-repo, default ..] → regenerates process.json
npm run pack        # build web + assemble deploy/ (server files + web/dist, no devDependencies)
npm run deploy      # pack + upload.js: SFTP upload of deploy/ using .env.deploy (gitignored), pinned host-key fingerprint, never deletes remote files
```

`test.js` is the only test. Extend it when changing API routes or business rules.

## Architecture

- `process.json` is generated by `sync-process.js` from `../src` (`data.js` phases/gates, `steps-detail.json` rows, `templates.json`). Don't hand-edit it. It also carries `roles` (the 8 RACI roles), per-gate `roles` (`GATE_ROLES`: who may sign) and per-step `templates[].required` (`REQUIRED`), all defined in `sync-process.js`.
  - Gate keys (`g1`, `g4a`…) and `requires` (Gate 4 needs 4a/4b/4c) are derived there.
  - So are `baseSteps` (first phase, B1–B2) and `fastTrackSkip` (parsed from the source's fastTrack text).
  - Template scope and repo path (`PLACES` table: `shared|cumulative|feature|event`, `{spec}` placeholder) are also set there.
- `server.js`:
  - Plugins plus an `onRequest` hook that does session lookup and the CSRF `Origin`/`Referer` host check on every non-GET.
  - Registers `lib/api.js` in its own scope, so the JSON error handler applies only to `/api`.
  - Serves `web/dist/assets/:file` (safe-name regex) and falls back to `index.html` for SPA routes.
- `lib/api.js`: all `/api/*` routes and all business rules. Write routes return the updated project via `withView(p, user)`, which adds `view` (per-track pct, current step, blocking/failed gates, per-step pct, missing required docs, per-gate `applies`/`blocker`/`roleBlocker`/`pendingAi`/`missingDocs`, plus project-level `setup` and `me`) computed by `lib/progress.js`. `view` is per viewer because `roleBlocker` and `me` depend on the user, so never cache it across users. The frontend never re-implements these rules, it only reads `view`. Errors are `{ error }` with 400/401/403/404/409.
- Data model: a project is a `base` track (B1–B2) plus `items[]` tracks (the remaining steps, kind `full|cr|fast`). A track is `{steps, gates}`. Docs link to a track via `doc.track` (`'base'` or item id). Step owners are `owners: [userId]`.
- AI governance data on the project: `members: [{userId, roles}]`, `aiSetup: {tools, dataLevel}`, `aiLogs[]` (`origin` ai|mixed|manual; `result` pending|accepted|edited|rejected|na, where manual entries are `na`), `repoType` gitlab|github. Items add `crCode`/`crReason` (kind cr) and `fastCheck` (kind fast).
- Rules in `lib/progress.js`: role enforcement is only on when `members` is non-empty (legacy projects stay open; `enforced()`); a gate needs one of `gate.roles`, and admin gets no bypass. Signing a gate `pass` is blocked while any AI log in the track up to the gate's step is `pending` (Human Gate). A reviewer must differ from the logger. Missing required docs only warn. `setupStatus()` gates item creation (soft block: only admin with `force: true` bypasses, and it is audited). Fast-track needs the 3 `FAST_QUESTIONS` answered correctly.
- Account admin routes (`/api/admin/users`: create, disabled, reset, `DELETE`) live in `lib/api.js`. `store.deleteUser` also strips the user from every project's `members` and step `owners`; sessions are revoked and the audit log keeps the old name. Admins can't disable or delete themselves.
- `lib/api-governance.js` holds the members, ai-setup, ai-logs and my-tasks and metrics routes, registered from `lib/api.js` with shared helpers. Prompt text is deliberately never stored, only purpose and prompt id.
- `lib/tasks.js` (`collectTasks`) is the single source for "my tasks", shared by `/api/my-tasks` and the bot's `/viec`. `lib/metrics.js` (`buildMetrics`, pure) feeds `/api/metrics` and the Reports page; gate pass/fail history is counted from audit lines (`Ký Gate N [...]`), step durations from `startedAt`/`doneAt` which the step route sets on status changes (absent on older data).
- Telegram: `lib/telegram.js` (Bot API client, long-poll loop, `/start CODE` linking, `/chatid`, `/viec`, DM sending, morning digest timer), `lib/notify.js` (pure: `diffEvents(before, after)` turns a project change into messages, `buildDigest`), `lib/api-telegram.js` (admin config + self-linking routes). `save()` in `lib/api.js` calls `tg.notifyDiff(req.project, after, actor)` after every project write, so notifications cover all routes without per-route code. The bot token lives only in `data/secrets.json` (excluded from backups, never returned by the API, never audited); settings in `data/settings.json`; user links in `users.json` as `user.tg`. `buildApp` takes `telegramFetch` so `test-telegram.js` runs against a fake Bot API with no network. `startDigestTimer()` starts only from the CLI block, like backups.
- `lib/sessions.js` persists sessions to `data/sessions.json` keyed by SHA-256 of the session id; `lib/backup.js` makes a daily `data-YYYY-MM-DD` copy into `BACKUP_DIR` (kept 14, `sessions.json` excluded), scheduled from `server.js` only when run as a CLI so tests never write backups.
- `lib/store.js`:
  - Synchronous read-modify-write of JSON files with tmp+rename, so only a single server process is safe.
  - Project ids are 8 hex chars (`ID_RE`), which also prevents path traversal.
  - `normalize()` migrates legacy flat `steps/gates` projects (rewritten on first load so item ids stay stable) and back-fills steps/gates added by a later sync.
  - `cleanRepo`/`cleanBranch`/`cleanSpecDir` validate repo info.
- `web/src`:
  - `api.ts` holds the fetch wrapper (401 → /login) and the query hooks. `useProjectMutation` writes the returned project into the `['project', id]` cache and invalidates `projects`/`log`.
  - `Shell.tsx`: `Layout.Sider` + `Menu` (collapsible, state in localStorage) + header with the account dropdown. `components.tsx` has `PageHeader`, `FormModal` (Modal + Form), `FilterBar`/`Field`, `options()`, `showTotal()`.
  - `pages/`: Dashboard (tree antd `Table`, local filter/sort/pagination), Project + StepCard (step form, checklist, docs, gate signing), Admin, Log, Login, Me.
  - `MdViewer.tsx`: `useDocViewer(pid)` returns `{open(doc), node}`, a Drawer with pretty (react-markdown + remark-gfm, **no rehype-raw**, so embedded HTML stays inert) and raw views. It reads `GET /api/projects/:id/docs/:docId/content` (text/plain + CSP sandbox). `pages/Docs.tsx` lists every project doc.
  - `util.ts`: `blob()`/`tplPath()` build GitHub/GitLab links. `fold()` makes search accent-insensitive.
  - Theme tokens live in `main.tsx`.
  - UX layer: `Term` + `GLOSSARY` in `components.tsx` (tooltip glossary), `pages/Help.tsx`, `pages/Reports.tsx`, `pages/Tasks.tsx`; StepCard has an unsaved-changes guard (`useBlocker`) and collapsible steps; Shell turns the Sider into a drawer below 992px. The sticky header is `zIndex: 20` and the project Anchor uses `offsetTop={56}` to sit below it.

## Gotchas

- Import the antd locale from `antd/es/locale/vi_VN`. The CJS `antd/locale/vi_VN` gets bundled wrong and silently falls back to English. Don't reintroduce Pro Components: it added about 200 KB brotli and pinned antd to v5.
- Root `npm run build` must `cd web && npm install`. `npm --prefix web install` installs the root package into web/ as `file:..`.
- Helmet's `referrerPolicy` must stay `same-origin`, or browsers send `Origin: null` and the CSRF check rejects everything. CSP needs `style-src 'unsafe-inline'` for antd's CSS-in-JS.
- The Vite proxy uses `changeOrigin: false` so Host matches Origin in dev.
- antd `Form` `initialValues` only apply on mount. The gate form is keyed by result/time so it reloads when a dependent gate is auto-reset.
- Uploads are Markdown only: the API checks the `.md` extension plus strict UTF-8 with no NUL bytes, max 5 MB (`MAX_UPLOAD` in `server.js`). The UI `Upload` mirrors this, but the server is the real check.
- Uploaded files are always served as `attachment`.
- When patching files with shell heredocs here, backslashes get halved (`\s` becomes `s`), so regexes silently break. Use the Edit/Write tools for any code containing backslashes.
- `npm run build` fails with EPERM if a running server holds `web/dist` open on Windows. Build elsewhere with `vite build --outDir <dir>` and serve it with `CMS_DIST=<dir>`, or stop the server first.

## Deployment

Runs on the user's Windows PC (host `datcty`): `start.bat` (idempotent, uses `%~dp0`, builds `web/dist` if missing, logs to `server.log`) serves :3300. Public URL https://cms-ai.btdat.io.vn comes from Cloudflare Tunnel `cms-ai-datcty` (Windows service, remotely managed; hostname mapping is in the Cloudflare dashboard). The static site `..` runs on :3200 behind the same tunnel. Auto-start after reboot needs shortcuts to both `start.bat` files in `shell:startup`. `deploy/` + `npm run deploy` is the older SFTP path.
